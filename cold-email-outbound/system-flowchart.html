Cold Email Outbound — System Architecture

● Franchise Sellers ● Company Sellers · v1 — 2026-05-21 · Companion to SYSTEM-DESIGN.md
Claude Code orchestrates a 10-layer pipeline. Pulls leads from existing archives + new sourcing APIs → enriches through a waterfall → scores + dedupes + suppresses against 5 sources → generates signal-anchored copy in 3-step sequences → sends through Instantly → classifies every reply via the Claude API → routes positives to the matching destination (GHL CRM for sellers, Buyer Manager pipeline for buyers, referral nurture for partners). The system runs multiple campaign streams in parallel — seller cold (FS niche + FS broad + CS), buyer reactivation, referral partner outreach, and event-tied micro-campaigns. Each stream shares the same engine (sourcing, enrichment, suppression, sending, classification) but has its own templates, ICP filter, list source, and reply-routing destination.

The 10 layers — one-line summary each

01 Sourcing archiveApollo (P2)public records
Phase 1 reactivation pulls entirely from the existing ~660K-row archive (Clay + Airtable + FS SAVE! + Dropbox). Phase 2+ adds Apollo for new firmographic sourcing. Phase 3 adds signal feeds (PDL job changes, news-API M&A detection, LinkedIn bio signals).
02 Enrichment Waterfall Apollo → PDL → Hunter → VerifierClaude API
Cheapest first. Apollo for firmographic, PDL or Datagma for owner age + tenure + job-change signals, Hunter/Snov/Findymail for email finder waterfall, NeverBounce/MillionVerifier for final pre-send gate. Claude API adds per-row signal extraction (M&A, "why now"). Skip entirely in Phase 1 — the archive already carries Clay's 6-provider waterfall enrichment.
03 Data Layer Airtable (P1)RevyOps (deferred)
Airtable's Active Contacts (18,931 × 48 cols) already cross-references Clay + Instantly + Pipedrive — it's a proto-RevyOps. Phase 1 recommendation: keep Airtable. Defer RevyOps decision until Phase 2 when scale + cost evidence is real. Records carry brand, ICP score, enrichment, suppression flags, campaign history, reply classification, re-engage date.
04 Dedupe + ICP Scoring Claude Code
Match by email + LinkedIn URL against data layer. Score 0–100 (40% demographic + tenure, 40% behavioral + situational, 20% firmographic). Threshold ≥ 60 to enter sequencing. Brand auto-assignment from data signals when not pre-tagged.
05 3-Layer Suppression pre-send filterInstantly block list
Layer A: pre-send filter unions 5+ sources — Clay Franchisee Block List (22K) + Dropbox DNU Master (172K) + Airtable Archived Contacts (38K) + Pipedrive 2022 (4K) + SMS Blast (12K) + in-CRM records (from crm-snapshot) + active cooldowns. Layer B: Instantly global block list synced every 4hr by Claude Code. Layer C: Live Instantly settings (stop_on_reply, stop_on_auto_reply). Gross suppression input ~250K; net unique ~150–200K. Reactivation pool will be substantially smaller than headline 660K.
06 Copy Generation (Spintax + Signal Anchoring) Claude APItemplates
Hand-written 3-step template based on the winning historical pattern: "We helped a [specific franchise] franchisee sell for more than they thought possible — and faster than they expected." 55–90 words. 3 subject variants per step. ≥50% content variation via spintax. AI fills surgical variables only ({{firstName}}, {{franchise_system}}, optional {{signal_anchor}}) — never full-paragraph generation. Offer rotation tests OOV control vs alternatives one at a time.
07 Sending Instantly
One Instantly org, brand-tagged campaigns. ~30 sending domains per brand × 2–3 mailboxes each ≈ 60–90 sending addresses per brand. Cold cap 25–30 sends/mailbox/day. Continuous warmup permanently on. Brand walls enforced — FS prospects only see FS sending domains.
08 Engagement Tracking Instantly webhooksClaude Code listener
Webhooks fire for sent / replied / bounced / unsubscribed. Claude Code listener writes back to data layer. Open + click tracking disabled by default — 2026 research shows pixel tracking flags as commercial mail. Track replies + opportunities only.
09 Reply Classification Claude API per message
Every inbound reply runs through Claude API → 11 categories: positive_meeting_ready, positive_curious, positive_with_timeline_objection, objection_not_now (extracts date), objection_not_interested, wrong_person, wrong_intent_buyer_side, unsubscribe, out_of_office (extracts return date), referral (extracts name), meeting_accepted. The biggest gap-fix vs. the prior engine — historically only 30% of replies were classifiable; this gets to 100%.
10 CRM Routing routing logicGHL FSGHL CS
Positive replies → matching GHL workspace (brand-tagged routing, never cross). Discovery Call workflow / OOV Intake workflow triggered by classification. Cooldowns + retries scheduled by Claude Code. Buyer-side intent routes to Yvonne's Buyer Manager pipeline, not cold-suppression. Closed-lost → 12mo cooldown. Closed-won → permanent customer flag.

Build phases

PHASE 1

Build framework + probe all streams (weeks 1–4)

  • Build the framework that supports all stream types as first-class concepts
  • Ship 500-record probes across all major streams in parallel: seller cold FS niche, seller cold CS, buyer reactivation, referral partner advisor, event pre-touch
  • Per-stream success gates (see metrics table below)
  • Build suppression engine, per-stream template library v1, reply classifier with per-stream routing
  • No net-new sourcing yet. Reactivate the existing ~660K archive across all streams
PHASE 2

Net-new sourcing (weeks 5–8)

  • Wire Apollo + enrichment waterfall
  • Sourcing pipeline producing ≥ 500 leads/week
  • Scale send volume to 6K/month
  • Refine ICP scoring with Phase 1 outcomes
  • Decision point: Airtable scaling check → migrate to RevyOps if needed
PHASE 3

Intent-signal + scale (months 2+)

  • PDL job-change feeds micro-campaigns
  • News-API + Claude detects M&A → triggers vertical micro-campaigns
  • 10–25 small targeted campaigns/month vs 1–2 big
  • Scale to 10K+/month
  • Move toward semi-autonomous campaign generation (Anthropic Managed Agents pattern)

⚠ Open decisions — settle before Phase 1 starts

  1. Airtable vs. RevyOps — recommend Airtable for Phase 1, defer RevyOps to a Phase 2 eval point
  2. PDL vs. Datagma for deep enrichment — recommend PDL (bigger DB, more established)
  3. Hunter vs. Snov vs. Findymail for email finder — recommend Findymail (highest accuracy on B2B work emails in recent benchmarks)
  4. Email verifier provider — Theodore action: confirm which provider was used previously and reactivate
  5. No-reply cooldown duration — default 60 days (confirm)
  6. Closed-lost cooldown duration — default 12 months (confirm)

What's grounded in research vs. opinion

Sources informing this design:

  • Your historical campaign data — 30 campaigns analyzed in INSTANTLY-CAMPAIGN-RETROSPECTIVE.md drove the template choice, sequence length, buyer-side prioritization, and the "no full-AI copy" rule.
  • Your existing data archive — 660K rows across Clay/Airtable/FS SAVE!/Dropbox catalogued in PHASE-0-DATABASE-AUDIT.md drove the suppression model (5 sources merged) and the Phase 1 reactivation-first approach.
  • 2026 public Claude Code outbound implementations — Salesforge's "How I Use Claude Code to Automate My Entire Cold Email Operation" (MCP-bridge pattern, 7-skill library), Databar.ai's "Cold Email in 2026" (micro-campaign velocity, 10–15% top reply rates), Anthropic's claude-agent-sdk-demos/email-agent (Client ↔ Agent ↔ Backend pattern with IMAP), Ben Reed's RevyOps framework on LinkedIn (data layer separation principle).
  • 2026 deliverability research — Verified lists 2× reply rate of unverified; spintax ≥ 50% recommended; open-tracking pixel hurts inbox placement (so we disable by default).
